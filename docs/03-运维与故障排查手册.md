> 适用对象：运维工程师 / 技术支持

## 0. 快速定位

### 0.1 先判断"坏在哪一层"

```
用户反馈"打不开 / 扫码报错"
        │
        ├─ 浏览器/小程序请求是否到达服务器？ ── 否 → DNS、备案、SSL、防火墙（第 2 章）
        │
        ├─ Nginx 是否返回 502/504？ ────────── 是 → 后端进程/端口（第 1、2 章）
        │
        ├─ 接口返回 500/业务错误码？ ────────── 是 → 应用日志 + MySQL/Redis（第 1、4 章）
        │
        └─ 页面正常但图片/视频异常？ ────────── 是 → 目录权限、防盗链、mp4（第 3 章）
```

## 1. Java 进程突然停止

### 1.1 现象

- 网站/小程序全部接口报 **502 Bad Gateway** 或连接超时。
- 宝塔 Java项目管理器中项目状态为「已停止」；`ss -lntp | grep 8080` 无输出。
- 有时系统会**自动拉起**（开启了守护），表现为"服务时好时坏"。

### 1.2 排查步骤（按顺序）

#### 第 1 步：确认进程与端口现状

```bash
ps -ef | grep -v grep | grep product-trace
ss -lntp | grep 8080
systemctl status product-trace --no-pager     # systemd 方式
```

- 有进程、无端口 → 正在启动或启动失败（看日志）。
- 无进程 → 已退出，进入第 2 步。

#### 第 2 步：看是不是"被系统杀掉"（内存不足最常见）

```bash
free -m
dmesg -T | grep -iE "out of memory|killed process|oom" | tail -n 20
```

若出现 `Killed process ... (java)` 或 `Out of memory: Killed process`，说明 **Linux OOM Killer** 杀掉了 Java，原因是物理内存不足。

处理：

1. 降低堆上限：`-Xms256m -Xmx512m`（2GB 内存机器）。
2. 限制 MySQL 内存：宝塔 → 数据库 → 配置修改 → `innodb_buffer_pool_size = 256M`。
3. 限制 Redis：`maxmemory 128mb`。
4. 若仍不足，升级服务器内存（推荐 4GB 起）。

#### 第 3 步：看应用日志最后 200 行

```bash
tail -n 200 /www/wwwroot/product-trace/logs/product-trace.log
journalctl -u product-trace -n 200 --no-pager
```

**关键错误关键字对照表**

| 日志关键字 | 含义 | 处理 |
| --- | --- | --- |
| `APPLICATION FAILED TO START` | 启动自检失败 | 看下方 `Description:` 具体原因 |
| `Port 8080 was already in use` | 端口被占用 | `lsof -i:8080` 找到进程并处理 |
| `Access denied for user 'product_trace'@'localhost'` | 数据库密码/权限错误 | 核对 `.env` 的 `DB_PASSWORD` 与宝塔数据库密码 |
| `Communications link failure` | MySQL 未启动/网络不通 | `systemctl status mysqld`，检查 3306 |
| `Unknown database 'product_trace'` | 库不存在 | 按部署手册第 3 章建库导入 |
| `Table 'product_trace.xxx' doesn't exist` | 未执行建表脚本 | 执行 `deploy/schema.sql` |
| `NOAUTH Authentication required` | Redis 需要密码但未配置 | 配置 `REDIS_PASSWORD` |
| `WRONGPASS invalid username-password pair` | Redis 密码错误 | 核对密码 |
| `Unable to connect to Redis` | Redis 未启动/端口不通 | 见第 4 章 |
| `OutOfMemoryError: Java heap space` | 堆内存不足 | 调大 `-Xmx` 或排查内存泄漏 |
| `OutOfMemoryError: Metaspace` | 元空间不足 | 调大 `-XX:MaxMetaspaceSize=256m` |
| `java.io.IOException: No space left on device` | 磁盘满 | `df -h` 清理日志/视频 |
| `java.lang.OutOfMemoryError: unable to create native thread` | 线程数超限 | 降低连接数、调大 `ulimit -u` |
| `FileNotFoundException: /www/wwwroot/media/uploads/...` | 目录不存在/无权限 | 创建目录并 `chown www:www` |

> 日志按天/10MB 轮转，找不到当次记录时用 `ls -lt /www/wwwroot/product-trace/logs/` 查看最新文件，或 `zgrep` 检索压缩日志。

#### 第 4 步：区分退出码

| 退出码 | 含义 | 常见原因 |
| --- | --- | --- |
| `143`（128+15） | 收到 SIGTERM | 人为停止、部署重启、内存回收脚本 |
| `137`（128+9） | 收到 SIGKILL | **OOM Killer**、强制 kill |
| `1` | 应用主动退出 | 启动异常（配置/依赖/建表） |
| `126` / `127` | 命令不可执行/找不到 | JDK 路径错误、jar 权限 |

```bash
systemctl show product-trace -p ExecMainStatus -p ExecMainCode
```

#### 第 5 步：检查磁盘与 inode

```bash
df -h
df -i
du -sh /www/wwwroot/media/uploads/* | sort -h | tail
```

磁盘满会导致：日志写失败 → 应用异常 → 上传失败 → MySQL 写入失败，表现往往是"突然全站不可用"。

清理建议：

```bash
# 清理 7 天前日志（谨慎，先确认）
find /www/wwwroot/product-trace/logs -name "*.gz" -mtime +7 -delete

# 查看媒体占用
du -sh /www/wwwroot/media/uploads/videos
```

> 不要直接 `rm -rf` 媒体目录；删除前确认数据库是否仍引用。

#### 第 6 步：检查配置是否被误改

```bash
# 查看实际生效的环境变量（不要在有他人的终端打印密码）
systemctl cat product-trace | grep -E "EnvironmentFile|ExecStart"
cat /www/wwwroot/product-trace/backend/.env

# 最近是否改过配置/上传过新 jar
ls -l --time-style=long-iso /www/wwwroot/product-trace/backend/
```

### 1.3 恢复服务

```bash
# systemd
systemctl restart product-trace
sleep 5
systemctl status product-trace --no-pager
curl -s http://127.0.0.1:8080/api/health

# 宝塔 Java 项目管理器
# 面板 → Java项目管理器 → product-trace → 启动
```

**验证顺序**

1. `ss -lntp | grep 8080` 有监听。
2. 本机 `/api/health` 返回 200。
3. 经 Nginx：`curl -sI https://api.yourdomain.com/api/health` 返回 200。
4. H5 打开 `https://h5.yourdomain.com/p/1` 正常。
5. 扫一个真实码，确认防伪结果正常。

### 1.4 预防措施

| 措施 | 说明 |
| --- | --- |
| 合理堆参数 | 4GB 机器：`-Xms512m -Xmx1024m`；2GB：`-Xms256m -Xmx512m` |
| 开启进程守护 | 宝塔 Java 项目「守护进程」或 systemd `Restart=always` |
| 日志轮转 | 已配置 `logging.file.name`，Spring Boot 默认 10MB 轮转、保留 7 天 |
| 磁盘监控 | 宝塔 → 监控 → 设置磁盘告警（≥85%） |
| 内存监控 | 宝塔监控 + 告警；`free -m` 常看 available |
| 变更留痕 | 每次升级保留 `product-trace.jar.bak_日期`，记录变更时间 |
| 不要定时重启 | 重启只能掩盖问题，优先定位根因 |

## 2. 扫码后出现 502 Bad Gateway

### 2.1 含义

`502` 表示 **Nginx 作为代理，无法从上游（`127.0.0.1:8080`）拿到有效响应**。绝大多数情况是 Java 后端没起来或中途挂了。

### 2.2 五步定位法

#### 第 1 步：确认是 502 还是别的错误

```bash
grep ' 502 ' /www/wwwlogs/api.yourdomain.com.log | tail -n 20
tail -n 100 /www/wwwlogs/api.yourdomain.com.error.log
```

错误日志常见内容：

| 日志内容 | 含义 |
| --- | --- |
| `connect() failed (111: Connection refused)` | 后端没监听 8080 |
| `upstream prematurely closed connection` | 后端处理中崩溃/重启 |
| `no live upstreams` | 后端完全不可用 |
| `upstream timed out (110: Connection timed out)` | 后端处理超时（通常是 504） |
| `SSL_do_handshake() failed` | 上游 HTTPS 配置错误（本项目为 HTTP，不应出现） |
| `client intended to send too large body` | 上传超过 `client_max_body_size`（413，不是 502） |

#### 第 2 步：绕过 Nginx 直连后端

```bash
curl -v -m 5 http://127.0.0.1:8080/api/health
```

- **能返回 JSON** → 后端正常，问题在 Nginx 配置（进入第 4 步）。
- **Connection refused** → 后端未启动（进入第 3 步）。
- **超时** → 后端卡死/线程池耗尽/GC 停顿。

#### 第 3 步：确认端口监听地址与进程

```bash
ss -lntp | grep 8080
ps -ef | grep -v grep | grep java
```

- 无输出 → 进程未启动：按第 1 章排查启动日志。
- 监听 `127.0.0.1:8080` → `proxy_pass http://127.0.0.1:8080` 可正常连接（本项目即如此）。
- 监听 `[::]:8080` 但 Nginx 配 `127.0.0.1` → 也可能失败，改为 `proxy_pass http://127.0.0.1:8080;` 并确认 `server.address` 未绑定到 IPv6。

#### 第 4 步：检查 Nginx 配置

```bash
nginx -T | grep -A 20 "location /api/"
```

必须满足：

| 检查点 | 正确值 | 错误示例 |
| --- | --- | --- |
| 反代地址 | `proxy_pass http://127.0.0.1:8080;` | `http://127.0.0.1:8081` |
| 是否保留 `/api` 前缀 | 不带路径（`...:8080;`） | `...:8080/;`（会丢失 `/api`，变成 404） |
| 站点是否包含该配置 | 放在 `api.yourdomain.com` 站点 | 配置写到了别的站点 |
| `map` 是否在 server 外 | 见 `bt_nginx_api.conf` 顶部 | 放进 `server {}` 会导致整份配置不生效 |

#### 第 5 步：确认不是"启动中"或"重启中"

```bash
journalctl -u product-trace -n 50 --no-pager | grep -E "Starting|Started|Tomcat started|Shutting"
```

Spring Boot 从启动到监听端口通常 10~30 秒。若重启脚本刚执行就访问，会短暂 502（属正常）。

### 2.3 常见原因与处理

| 原因 | 判断依据 | 处理 |
| --- | --- | --- |
| 后端进程停止 | 端口无监听 | 第 1 章恢复 |
| 后端启动失败（配置/DB/Redis） | 日志 `APPLICATION FAILED TO START` | 修正配置后重启 |
| 端口配置不一致 | `server.port` vs `proxy_pass` | 统一为 8080 |
| 上下文路径错误 | 直连 `/health` 404、`/api/health` 200 | `proxy_pass` 不能带 `/` 后缀 |
| Nginx 配置未重载 | 改完配置未 reload | `nginx -t && nginx -s reload` |
| 后端线程池耗尽 | 日志大量超时、CPU 高 | 排查慢 SQL、Redis 阻塞；扩容 |
| GC 长时间停顿 | `jstat -gc <pid>` Full GC 频繁 | 调大堆、排查内存泄漏 |
| 健康检查端口被防火墙拦截 | 本机 curl 通、反代不通（少见） | `iptables -L -n`、`firewall-cmd --list-all` |
| SELinux 阻止代理 | `getenforce` = Enforcing，日志有 avc denied | `setsebool -P httpd_can_network_connect 1` |
| 上传过大返回 413 | `client intended to send too large body` | 调大 `client_max_body_size` 与 Spring 上限 |

> **502 vs 504**：502 是"连不上/连接被断"，504 是"连上了但后端超时"。504 优先查慢查询（如大批量生成期间同时访问）与 `proxy_read_timeout`。

### 2.4 恢复后验证

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://api.yourdomain.com/api/health
curl -s https://api.yourdomain.com/api/health/db
curl -s -o /dev/null -w "%{http_code}\n" \
  -X OPTIONS https://api.yourdomain.com/api/verify/TEST \
  -H "Origin: https://h5.yourdomain.com" -H "Access-Control-Request-Method: GET"
```

期望：`200` / `"allTablesReady":true` / `204`。

## 3. 图片无法显示 / 视频无法播放

### 3.1 先区分 404 与 403

| 状态码 | 含义 | 主要方向 |
| --- | --- | --- |
| `404` | 文件不存在 / 路径不匹配 | 存储目录、URL 前缀、日期目录 |
| `403` | 被拒绝访问 | 视频防盗链、文件权限、隐藏文件规则 |
| `200` 但黑屏 | 编码/浏览器不支持 | 视频编码、faststart |
| `206` 才能拖动 | Range 生效 | 见 3.4 |
| `CORS` 报错 | 跨域头缺失 | 见 3.5 |

用浏览器 F12 → Network 查看具体状态码与 URL，再对照下表。

### 3.2 图片 404

**原因 1：后端存储路径与 Nginx root 不一致**

```bash
# 后端实际落盘目录
grep -n "root-path" /www/wwwroot/product-trace/backend/.env 2>/dev/null
ls -l /www/wwwroot/media/uploads/images/$(date +%Y/%m/%d)/ | head

# Nginx root
nginx -T | grep -E "root |location /uploads"
```

正确关系：

| 项 | 值 |
| --- | --- |
| 后端 `root-path` | `/www/wwwroot/media/uploads` |
| 落盘文件 | `/www/wwwroot/media/uploads/images/2026/10/21/xxx.jpg` |
| Nginx `root` | `/www/wwwroot/media` |
| 对外 URL | `https://api.yourdomain.com/uploads/images/2026/10/21/xxx.jpg` |

**原因 2：URL 前缀配置错误**

检查 `application-prod.yml`（或环境变量）中的 `media.storage.local.url-prefix` 是否为 `https://api.yourdomain.com/uploads`。若为 `http://`、`127.0.0.1` 或旧域名，前台会 404/混合内容。

**原因 3：文件权限**

```bash
namei -l /www/wwwroot/media/uploads/images/2026/10/21/xxx.jpg
```

要求：目录 `755`、文件 `644`、属主 `www`。修复：

```bash
chown -R www:www /www/wwwroot/media
find /www/wwwroot/media -type d -exec chmod 755 {} \;
find /www/wwwroot/media -type f -exec chmod 644 {} \;
```

**原因 4：日期目录不存在**

上传时按 `年/月/日` 建目录，若磁盘满或权限不足会创建失败。日志中会出现「创建存储目录失败」。

### 3.3 视频 403（防盗链误拦截，最常见）

#### 判断

```bash
# 不带 Referer（模拟小程序/直接访问）应 200
curl -sI https://api.yourdomain.com/uploads/videos/2026/10/21/xxx.mp4 | head -n 1

# 带 H5 域名 Referer 应 200
curl -sI -e "https://h5.yourdomain.com/" https://api.yourdomain.com/uploads/videos/2026/10/21/xxx.mp4 | head -n 1

# 带其他站点 Referer 应 403（防盗链生效）
curl -sI -e "https://evil.example.com/" https://api.yourdomain.com/uploads/videos/2026/10/21/xxx.mp4 | head -n 1
```

若第 1、2 条也是 403，说明白名单配置有问题或文件权限异常。

#### 当前白名单（`bt_nginx_api.conf`）

```nginx
valid_referers none server_names ~servicewechat\.com h5.yourdomain.com yourdomain.com *.yourdomain.com;
if ($invalid_referer) {
    return 403;
}
```

含义：

| 项 | 允许的情况 |
| --- | --- |
| `none` | 请求**没有** Referer 头（小程序 video 组件、部分播放器、直接访问） |
| `server_names` | 本站 `server_name`（`api.yourdomain.com`） |
| `~servicewechat\.com` | 微信内置来源 |
| `h5.yourdomain.com` | H5 站点 |
| `yourdomain.com` / `*.yourdomain.com` | 主域及子域（后台、其他页面） |

#### 快速放行（按影响面从小到大）

**方案 A：加入具体来源域名（推荐）**

若 H5 使用了新域名、或通过 CDN/第三方落地页引用：

```nginx
valid_referers none blocked server_names
    ~servicewechat\.com
    h5.yourdomain.com
    new-h5.yourdomain.com        # 新增
    yourdomain.com *.yourdomain.com;
```

```bash
nginx -t && nginx -s reload
```

> `blocked` 表示 Referer 存在但被隐私策略抹去（如 `Referrer-Policy: no-referrer` 场景），加上它可减少误杀；是否允许取决于安全策略。

**方案 B：临时关闭该目录防盗链（仅排障用，10 分钟内恢复）**

```nginx
location /uploads/videos/ {
    # valid_referers none server_names ~servicewechat\.com ...
    # if ($invalid_referer) { return 403; }
    try_files $uri =404;
    mp4;
    add_header Accept-Ranges bytes always;
}
```

```bash
cp /www/server/panel/vhost/nginx/api.yourdomain.com.conf /root/api.conf.bak_$(date +%s)
# 修改后
nginx -t && nginx -s reload
```

排障结束后**务必恢复**防盗链，否则视频可被任意外链盗用（流量与版权风险）。

**方案 C：确认是否为文件权限导致的 403**

```bash
ls -l /www/wwwroot/media/uploads/videos/2026/10/21/ | head
namei -l /www/wwwroot/media/uploads/videos/2026/10/21/xxx.mp4
```

### 3.4 视频能播放但**不能拖动进度条**

依赖三个条件，缺一不可：

| 条件 | 检查命令 | 修复 |
| --- | --- | --- |
| 服务端支持 Range，返回 206 | `curl -sI -H "Range: bytes=0-1023" https://api.yourdomain.com/uploads/videos/...mp4 \| head -n 3` | 确认 Nginx 未关闭 `Accept-Ranges`；静态文件服务默认支持 |
| MP4 的 `moov` 在文件头（faststart） | `ffprobe -v error -show_entries format=format_name,duration -of default=nw=1 文件.mp4` | `ffmpeg -i in.mp4 -c copy -movflags +faststart out.mp4` |
| Nginx 编译了 `http_mp4_module`（使用 `mp4;` 指令时） | `nginx -V 2>&1 \| tr ' ' '\n' \| grep http_mp4_module` | 若缺失：删除配置中的 `mp4;`、`mp4_buffer_size`、`mp4_max_buffer_size`，依靠 faststart + Range 即可拖动 |

**期望响应头**

```
HTTP/1.1 206 Partial Content
Content-Range: bytes 0-1023/10485760
Accept-Ranges: bytes
Content-Type: video/mp4
```

若返回 `200` 且无 `Content-Range`，说明 Range 未生效，检查是否被 CDN/代理缓存或 Nginx 配置覆盖。

**转码建议**：后端上传时已用 FFmpeg 生成 H.264 + AAC + `+faststart`。若手动放入视频，请按此规格处理，否则 iOS/微信可能黑屏。

### 3.5 图片/视频跨域或混合内容

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 控制台 `blocked by CORS policy` | `/uploads/` 缺少 CORS 头 | 配置已加 `Access-Control-Allow-Origin *`；确认未被宝塔「防盗链」插件覆盖 |
| `Mixed Content: https 页面加载 http 资源` | 媒体 URL 为 `http://` 或 `127.0.0.1` | 修正 `url-prefix`，重新保存产品数据 |
| 微信内图片不显示 | 图片域名非 https / 证书异常 | 使用 `https://api.yourdomain.com` |
| `net::ERR_CERT_*` | 证书过期/域名不匹配 | 宝塔 SSL 重新申请，检查证书覆盖域名 |

### 3.6 WebP 未生效（不影响可用性）

```bash
# 是否生成了 .webp
ls -l /www/wwwroot/media/uploads/images/2026/10/21/ | grep webp

# 响应头是否协商
curl -sI -H "Accept: image/webp" https://api.yourdomain.com/uploads/images/2026/10/21/xxx.jpg | grep -iE "content-type|vary"

# cwebp 是否可用
cwebp -version
```

| 情况 | 处理 |
| --- | --- |
| 无 `.webp` 文件 | 安装 `libwebp-tools`（或 `webp`），重新上传；存量图片执行 `convert-webp.sh` |
| 有 `.webp` 但返回 `image/jpeg` | 检查 `map $http_accept $trace_webp_suffix` 是否在 `http` 上下文、`try_files` 是否含 `$uri$trace_webp_suffix` |
| 脚本转换失败 | 用 `www` 用户执行，确认目录可写：`su -s /bin/bash www -c 'bash .../convert-webp.sh'` |

> WebP 是**性能优化**，失败会自动回退原图，不会造成图片 404。

## 4. Redis 连接失败的常见原因

### 4.1 影响面（为什么必须优先处理）

Redis 在本系统中承担 **4 项关键职责**，一旦不可用：

| 功能 | 影响 |
| --- | --- |
| 防伪验证计数 | `/api/verify/{code}` 直接 500，扫码全部失败 |
| IP 限流 | 拦截器执行 Lua 失败 → 500（限流失效但不放行） |
| 批量生成进度 | 任务进度无法读写，可能一直 `RUNNING` |
| 微信 access_token / jsapi_ticket 缓存 | 小程序码生成、H5 分享失败 |

> 注意：`/api/health` **不检查 Redis**（只检查 DB 与存储策略），Redis 故障时健康检查仍可能返回 `UP`。请用 `redis-cli ping` 单独确认。

### 4.2 排查步骤

#### 第 1 步：确认 Redis 进程与端口

```bash
ps -ef | grep -v grep | grep redis
ss -lntp | grep 6379
systemctl status redis --no-pager    # 或 /etc/init.d/redis status
```

#### 第 2 步：命令行连通性

```bash
redis-cli -h 127.0.0.1 -p 6379 ping
# 若返回 (error) NOAUTH Authentication required. → 需要密码，见第 3 步

redis-cli -h 127.0.0.1 -p 6379 -a 'Redis密码' ping
# 期望：PONG
```

#### 第 3 步：核对配置

```bash
redis-cli -h 127.0.0.1 -p 6379 -a 'Redis密码' config get requirepass
redis-cli -h 127.0.0.1 -p 6379 -a 'Redis密码' config get bind
redis-cli -h 127.0.0.1 -p 6379 -a 'Redis密码' config get protected-mode
redis-cli -h 127.0.0.1 -p 6379 -a 'Redis密码' config get maxmemory maxmemory-policy
```

要求：

| 配置 | 建议值 |
| --- | --- |
| `bind` | `127.0.0.1`（仅本机） |
| `protected-mode` | `yes` |
| `requirepass` | 强密码，且与后端 `REDIS_PASSWORD` **完全一致** |
| `maxmemory` | 至少 256mb（视扫码量） |
| `maxmemory-policy` | `noeviction`（避免淘汰限流/计数 key） |
| `timeout` | `0`（应用侧已配置 5s 超时） |

#### 第 4 步：查看 Redis 日志

```bash
tail -n 100 /www/server/redis/redis.log
```

| 日志关键字 | 含义 | 处理 |
| --- | --- | --- |
| `OOM command not allowed` | 达到 `maxmemory` 且策略为 noeviction | 扩容/清理无 TTL 的 key |
| `Can't save in background: fork` | 内存不足导致 RDB 失败 | 增大内存或关闭 RDB 持久化 |
| `Ready to accept connections` | 正常启动 | — |
| `Wrong signature trying to load DB` | 持久化文件损坏 | 备份后删除 dump.rdb 重启（会丢缓存，影响见下文） |
| `Address already in use` | 端口被占用 | 查找占用进程 |

#### 第 5 步：确认后端配置的实际值

```bash
grep -E "REDIS_PASSWORD|SPRING_PROFILES_ACTIVE" /www/wwwroot/product-trace/backend/.env
grep -iE "redis" /www/wwwroot/product-trace/logs/product-trace.log | tail -n 30
```

### 4.3 常见错误与修复

| 错误信息 | 原因 | 修复 |
| --- | --- | --- |
| `NOAUTH Authentication required` | Redis 已设密码，后端未配 | `.env` 添加 `REDIS_PASSWORD=...` 并重启 |
| `WRONGPASS invalid username-password pair` | 密码不一致（含特殊字符转义问题） | 用单引号包裹密码；避免 `#`、空格；重设一致密码 |
| `Connection refused` | Redis 未启动 / 端口改过 | 启动服务；核对 `port` |
| `Unable to connect to Redis` / `RedisConnectionFailureException` | 网络/绑定地址问题 | 确认 `bind 127.0.0.1` 与后端 `host=127.0.0.1` |
| `Read timed out` | Redis 阻塞（大 key、慢命令） | `redis-cli --bigkeys`、`SLOWLOG GET 10` |
| `Could not get a resource from the pool` | Lettuce 连接池耗尽 | 检查是否有阻塞命令、连接泄漏；适当增大 `max-active` |
| `ERR max number of clients reached` | 连接数超限 | `config get maxclients`；排查异常连接 |
| `DENIED Redis is running in protected mode` | 保护模式 + 非本机访问 | 保持本机访问，或显式配置密码与 bind |

### 4.4 修复后的验证

```bash
redis-cli -h 127.0.0.1 -p 6379 -a 'Redis密码' ping
systemctl restart product-trace

# 扫码功能（替换为真实码值，注意限流 30 次/分钟）
curl -s https://api.yourdomain.com/api/verify/真实码值

# 限流 key 是否写入
redis-cli -a 'Redis密码' --scan --pattern 'rate:verify:ip:*' | head
```

### 4.5 高风险操作警告

| 操作 | 后果 | 建议 |
| --- | --- | --- |
| `FLUSHALL` / `FLUSHDB` | **清空扫码次数、限流窗口、批量任务进度、微信 token**，防伪计数回到数据库历史值，可能让复制的真码重新"变正品" | 严禁在生产随手执行；必须清时先导出 `trace:code:*` 并评估 |
| 直接删除 `dump.rdb` 重启 | 丢失全部缓存与任务进度 | 仅在确认无进行中批量任务时操作 |
| 关闭 Redis 密码"图省事" | 面板/端口暴露时被写入恶意 key | 保持密码，仅监听 127.0.0.1 |
| 将 `maxmemory-policy` 改为 `allkeys-lru` | 内存满时淘汰限流 key，限流被绕过 | 使用 `noeviction` 并监控内存 |

> 若必须临时清理某类 key，请精确删除，例如：
> ```bash
> redis-cli -a '密码' DEL trace:code:meta:ABCD1234
> redis-cli -a '密码' DEL trace:code:scan:ABCD1234
> ```

## 5. 附录

### 5.1 故障应急处理顺序

```
1. 确认影响范围（全站 / 单接口 / 单产品）
2. 保留现场：复制日志片段、记录时间与请求 URL/码值
3. 快速恢复：重启服务或回滚 jar / H5 / 配置（优先恢复业务）
4. 验证：健康检查 + 真实扫码 + 关键页面
5. 根因分析：对照本手册对应章节，修复后补监控与预防措施
6. 记录：变更时间、原因、处理人、验证结果
```

### 5.2 服务重启与回滚速查

```bash
# 后端重启
systemctl restart product-trace

# 后端回滚
cd /www/wwwroot/product-trace/backend
cp product-trace.jar product-trace.jar.failed_$(date +%Y%m%d%H%M)
cp product-trace.jar.bak_YYYYMMDDHHMM product-trace.jar
chown www:www product-trace.jar
systemctl restart product-trace

# Nginx 配置回滚
cp /root/api.conf.bak_xxxx /www/server/panel/vhost/nginx/api.yourdomain.com.conf
nginx -t && nginx -s reload

# H5 回滚
cd /www/wwwroot/product-trace/h5
mv dist dist_failed_$(date +%Y%m%d%H%M) && mv dist_bak_YYYYMMDDHHMM dist
chown -R www:www dist
```

### 5.3 备份与恢复

**数据库（建议每日 02:00 计划任务）**

```bash
mkdir -p /www/backup
mysqldump -uproduct_trace -p'密码' --single-transaction --routines --triggers product_trace \
  | gzip > /www/backup/product_trace_$(date +%F).sql.gz
find /www/backup -name "product_trace_*.sql.gz" -mtime +14 -delete
```

恢复（谨慎，会覆盖现有数据）：

```bash
gunzip -c /www/backup/product_trace_2026-10-20.sql.gz | mysql -uproduct_trace -p'密码' product_trace
```

**媒体文件（建议每周）**

```bash
tar -czf /www/backup/media_$(date +%F).tar.gz -C /www/wwwroot media/uploads
```

> 媒体文件可能较大，建议使用宝塔「计划任务 → 备份网站/目录」或对象存储同步；备份文件不要放在 Web 根目录下。

### 5.4 安全加固清单

| 项 | 要求 |
| --- | --- |
| 后端端口 | 8080 仅本机访问，安全组/防火墙**不放行** |
| Redis | `bind 127.0.0.1` + 强密码 + `protected-mode yes` |
| MySQL | 仅 localhost；应用账号最小权限；禁止 root 远程 |
| 宝塔面板 | 修改默认端口、开启面板 SSL、绑定访问 IP、开启双因素 |
| SSH | 禁用密码登录（改密钥）、修改 22 端口、fail2ban |
| CSV | 禁止公网直链（已配置 `location ^~ /uploads/csv/ { deny all; }`） |
| 日志 | 不记录明文密码；`.env` 权限 600 |
| 证书 | 开启自动续签并监控到期 |
