# 系统后台使用手册

> 项目名称：产品数字化展示与一物一码溯源系统
> 文档版本：v1.0（阶段四交付）
> 适用对象：运营人员 / 品牌方产品管理员（无需技术背景）
> 后台地址：`https://admin.yourdomain.com`（以实施人员提供为准）

## 0. 阅读说明

### 0.1 本手册能帮你完成什么

| 你想做的事 | 对应章节 |
| --- | --- |
| 登录后台 | 第 1 章 |
| 新建/编辑一个产品，上传图片视频、排版图文详情、上架 | 第 2 章 |
| 给产品生成一张普通小程序码（一个产品一个码） | 第 3 章 |

### 0.2 界面约定

后台采用左侧菜单 + 右侧内容区的经典布局，主要菜单如下：

```
├── 数据概览
├── 产品管理
│   ├── 产品列表
│   └── 新增产品

│   └── 假货预警
└── 系统设置

    └── 管理员账号
```

> **版本说明**：本手册按最终控制台界面编写，操作名称与菜单路径以实际页面为准。
> 当前交付版本中，产品、媒体上传、二维码、批量生成等**接口能力已全部上线**；若控制台某个页面尚未开放，可按 **附录 A** 的接口完成完全相同的操作，数据结果一致（建议由实施人员协助首次操作）。

### 0.3 三个必须理解的概念

| 概念 | 含义 | 使用场景 |
| --- | --- | --- |
| **普通产品码** | 同一产品的所有包装**共用同一个码**，可无限次扫码 | 宣传物料、电商详情页、产品图册 |
| **一物一码** | 每一件商品一个**唯一码**，可限制扫码次数，超过阈值判定为假货预警 | 防伪溯源、渠道管控、印刷在包装上 |
| **防伪阈值** | 一个一物一码允许被正常扫描的次数。阈值设为 3，表示第 1~3 次为正品，**第 4 次起弹出红色假货预警** | 防止真码被复制到假货上反复使用 |

## 1. 登录后台

### 1.1 登录步骤

1. 打开浏览器（推荐 Chrome / Edge），输入后台地址：`https://admin.yourdomain.com`。
2. 在登录页输入：
   - 账号：`admin`
   - 密码：`admin123`（首次交付默认密码）
3. 点击 **登录**。
4. 首次登录后，页面会提示修改密码；请点击右上角头像 → **修改密码**，设置 8 位以上、包含字母与数字的新密码。

> 🔐 **安全要求**：默认密码仅用于首次登录，正式上线前必须修改。请勿把账号密码写在便签或群聊中。

### 1.2 登录常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 提示"账号或密码错误" | 密码输入错误 / 大小写 | 确认 CapsLock；联系管理员重置 |
| 页面打不开、提示证书错误 | SSL 证书未生效 / 域名解析未完成 | 联系运维（见《运维与故障排查手册》第 2 章） |
| 登录后空白 | 浏览器缓存 / 接口异常 | 强制刷新（Ctrl+F5），仍异常则联系运维 |
| 提示"登录已过期" | 长时间未操作 | 重新登录 |

### 1.3 忘记密码（由运维执行）

后台密码使用 BCrypt 加密存储，无法直接查看。请运维在宝塔 → 数据库 → phpMyAdmin 中执行：

```sql
-- 将密码重置为 admin123（对应下方 BCrypt 值），登录后立即修改
UPDATE sys_admin
SET password = '$2a$10$N.zmdr9k7uOCQb376NoUnuTJ8iAt6Z5EHsM8lE9lBOsl7iKTVKIUi'
WHERE username = 'admin';
```

## 2. 产品管理

### 2.1 新建产品全流程

```
产品管理 → 新增产品 → 填写基础信息 → 上传封面/轮播图 → 上传视频
→ 编辑富文本详情 → 保存 → 预览 → 上架
```

#### 步骤 1：进入新增页

左侧菜单 **产品管理 → 产品列表** → 右上角 **+ 新增产品**。

#### 步骤 2：填写基础信息

带 `*` 为必填项。

| 字段 | 必填 | 填写说明 | 示例 |
| --- | --- | --- | --- |
| 产品编号 `productNo` | ✅ | 内部唯一编号，保存后不建议修改；不可重复 | `P2026001` |
| 产品名称 `productName` | ✅ | 展示给消费者的名称 | `有机山茶油 500ml` |
| 产品分类 `category` | — | 用于筛选，建议统一命名 | `食用油` |
| 品牌 `brand` | — | 品牌名称 | `山野坊` |
| 产地 `origin` | — | 原料/生产地 | `江西井冈山` |
| 规格 `spec` | — | 净含量/尺寸等 | `500ml/瓶` |
| 排序值 `sortOrder` | — | 数值越大越靠前，默认 0 | `100` |
| 上架状态 `shelfStatus` | ✅ | 上架=1，下架=0。**下架后扫码会提示"产品已下架"** | `上架` |

#### 步骤 3：上传封面图与轮播图

1. 在 **封面图** 区域点击 **上传图片**，选择本地图片。
2. 在 **轮播图** 区域点击 **上传图片**，可一次选择多张（建议 3~5 张）。
3. 上传成功后，图片会显示缩略图，可拖动排序、点击删除。

**图片规范（务必遵守，否则影响加载速度）**

| 项目 | 建议 |
| --- | --- |
| 格式 | JPG / PNG（系统会自动生成 WebP 副本加速） |
| 尺寸 | 正方形 750×750 或 1080×1080；详情图宽度 ≤ 1080px |
| 单张大小 | ≤ 5 MB（系统上限 500MB，但大图会拖慢用户打开速度） |
| 数量 | 轮播 1~8 张，建议 3~5 张 |

> 上传后图片地址形如 `https://api.yourdomain.com/uploads/images/2026/10/21/xxxx.jpg`，可直接复制到富文本中使用。
> 若图片不显示，请查看《运维与故障排查手册》第 3 章（多为目录权限或防盗链问题）。

#### 步骤 4：上传产品视频（可选）

**推荐做法**

1. 视频先用工具（剪映/HandBrake）导出为 **MP4（H.264 + AAC）**，分辨率 1080p，时长 ≤ 60 秒，文件 ≤ 100MB。
2. 在 **产品视频** 区域点击 **上传视频**。
   - 上传成功后系统会自动转码为可拖动播放的 MP4（需要服务器已安装 FFmpeg，由运维确认）。
3. 若当前控制台未开放视频上传按钮，可让运维将视频放入服务器目录
   `/www/wwwroot/media/uploads/videos/年/月/日/`，然后把访问地址填入 **视频地址** 字段，例如：

```
https://api.yourdomain.com/uploads/videos/2026/10/21/intro.mp4
```

> 视频必须使用 `https://api.yourdomain.com/...` 域名，不能填 `127.0.0.1` 或 `http://`（会导致小程序与 H5 无法播放）。

#### 步骤 5：编辑富文本详情

在 **产品详情** 富文本编辑区完成图文排版：

| 操作 | 说明 |
| --- | --- |
| 插入图片 | 使用编辑器工具栏的图片按钮上传，或把已上传图片地址粘贴进"网络图片" |
| 标题层级 | 使用 H2/H3，避免 H1（页面已有主标题） |
| 段落 | 每段不超过 4 行，移动端阅读更舒适 |
| 表格 | 参数类信息（成分、保质期）建议用表格，不要用空格对齐 |
| 视频 | 富文本中**不要**嵌入视频，请使用"产品视频"字段 |
| 外部链接 | 避免插入淘宝/京东等购买链接（本系统为纯展示，无购买功能） |
| 脚本/iframe | **禁止**粘贴 `<script>`、`<iframe>`，会被过滤且可能提交失败 |

> 富文本内容会原样展示在用户端详情页，建议保存前点击 **预览** 在手机尺寸下检查一次。

#### 步骤 6：保存与发布

1. 点击 **保存**：仅保存草稿，用户端不可见（取决于上架状态）。
2. 点击 **保存并上架**（或编辑时把"上架状态"改为上架）：用户扫码即可看到。
3. 在列表页确认状态为 **已上架**。

#### 步骤 7：自测

1. 列表页点击该产品的 **二维码** 按钮，生成普通产品码（见第 3 章）。
2. 用手机扫码，确认：轮播图正常、视频可播放、富文本无错位。
3. 若显示"产品已下架"或"产品不存在"，检查上架状态是否保存成功。

### 2.2 编辑、下架、删除

| 操作 | 路径 | 说明 |
| --- | --- | --- |
| 编辑 | 列表 → 操作 → **编辑** | 修改后保存，用户端刷新即生效 |
| 下架 | 列表 → 状态开关，或编辑页改"下架" | 扫码提示"产品已下架"；**已印刷的码不会失效**，只是暂时不可看 |
| 删除 | 列表 → 操作 → **删除** | 逻辑删除，列表中不再显示；已印刷码扫码提示"产品码不存在" |

> ⚠️ 删除产品前请确认该产品的码是否已印刷投放；删除会导致所有码失效且不可恢复（需运维从数据库恢复）。

### 2.3 产品列表筛选

- 关键词：支持产品名称/编号模糊搜索。
- 上架状态：已上架 / 已下架。
- 每页条数：默认 10 条，可切换 20/50。

## 3. 生成普通产品码（小程序码）

> 适用场景：一个产品一个码，可无限扫码，用于宣传物料、详情页、产品图册。

### 3.1 前置条件

| 条件 | 说明 |
| --- | --- |
| 产品已保存 | 必须先有产品 ID |
| 小程序 AppID/Secret 已配置 | 由运维在后端环境变量中配置 `WX_MINIAPP_APP_ID` / `WX_MINIAPP_APP_SECRET` |
| 小程序已发布 | 小程序码指向页面 `pages/product/detail`，该页面需在已发布版本中存在 |

### 3.2 操作步骤

1. 左侧 **二维码管理 → 普通产品码**。
2. 在列表中选择目标产品（或从产品列表点击 **二维码**）。
3. 点击 **生成小程序码**。
4. 等待 1~3 秒，页面显示：
   - 小程序码图片
   - 码值（如 `A1B2C3D4`）
   - 扫码上限：`不限`
5. 点击 **下载图片**（PNG，430×430），或右键图片另存为。

### 3.3 使用与印刷建议

| 项目 | 建议 |
| --- | --- |
| 印刷尺寸 | 直径 ≥ 25mm（太小小程序无法识别） |
| 留白 | 码四周保留 ≥ 3mm 白边，不要压图 |
| 材质 | 避免深色底、反光膜；深色包装请加白底 |
| 位置 | 平面、避免折角与接缝处 |
| 测试 | 印刷前用 3 台不同手机扫码测试；印刷后再抽检 |

> 同一产品重复点击"生成"不会生成新码，会返回**已有的那张码**（一产品一码）。若需重新生成，请联系运维在数据库中作废旧码后重新生成。

### 3.4 扫码后的效果

- 微信扫码 → 打开小程序产品详情页 → 顶部显示绿色"正品验证通过"提示。
- 普通码默认**不限扫码次数**，因此不会出现假货预警。

### 3.5 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 提示"微信小程序 AppID/AppSecret 未配置" | 后端未配置小程序密钥 | 联系运维配置环境变量并重启 |
| 生成的码是黑白方块占位图 | 本地联调 mock 模式 | 联系运维确认 `wx.miniapp.mock=false` |
| 提示 errcode=41030 | 小程序页面路径不存在/未发布 | 发布含详情页的小程序版本 |
| 提示 errcode=40001 | AppSecret 错误或 access_token 失效 | 运维核对 Secret，清除 Redis `wx:miniapp:access_token` |
| 扫码提示"产品已下架" | 产品未上架 | 产品管理 → 上架 |

## 4. 一物一码批量生成

> 适用场景：每一件商品一个唯一码，可设置扫码次数上限，用于防伪与渠道管控。

### 4.1 生成前确认

| 确认项 | 说明 |
| --- | --- |
| 产品已上架 | 未上架时扫码会提示"产品已下架" |
| 生成数量 | 单批 1 ~ 100,000 个 |
| 防伪阈值 | 默认 3（第 4 次扫码预警），可在"系统设置 → 防伪阈值"或生成前确认 |
| 批次号 | 建议填写可识别批次，如 `B20261021-A`；留空系统自动生成 `B+时间戳` |
| 磁盘空间 | 10 万个码约占用几十 MB（数据库 + CSV），属正常范围 |

### 4.2 操作步骤

1. 左侧 **二维码管理 → 一物一码批次** → 点击 **批量生成**。
2. 填写表单：

| 字段 | 说明 |
| --- | --- |
| 产品 | 下拉选择目标产品（必选） |
| 生成数量 | 例如 `10000` |
| 批次号 | 例如 `B20261021-A`（可留空） |

3. 点击 **开始生成**。
4. 系统立即返回一个**任务 ID**，并进入进度页面（生成在后台异步执行，**不要关闭页面也可以，但请勿重复提交**）。

### 4.3 查看生成进度

进度页面每隔约 2 秒自动刷新，显示：

| 显示项 | 说明 |
| --- | --- |
| 任务 ID | 用于查询与下载 |
| 批次号 | 本次生成批次 |
| 总数 | 计划生成数量 |
| 已生成 | 实时完成的个数 |
| 进度条 | 已生成 / 总数 |
| 状态 | `RUNNING` 生成中 / `SUCCESS` 已完成 / `FAILED` 失败 |
| 样例码值 | 前 5 个码，可用于快速测试 |
| 下载地址 | 完成后出现"下载 CSV"按钮 |

**耗时参考**：1 万个码通常数十秒内完成；10 万个码视服务器性能而定。生成期间可继续操作后台其他页面，稍后回到 **一物一码批次** 列表按任务 ID 查询。

> 若状态长时间停留在 `RUNNING` 且"已生成"不再增长，请记下任务 ID 联系运维（见《运维与故障排查手册》第 1、4 章，多为数据库或 Redis 异常）。
> 若显示 `FAILED`，页面会给出失败原因（如数据库连接失败、磁盘空间不足）。

### 4.4 下载 CSV

1. 状态为 `SUCCESS` 后，点击 **下载 CSV**。
2. 浏览器保存文件，文件名形如 `product_1_B20261021-A.csv`。
3. 用 Excel 打开（已带 UTF-8 BOM，中文不会乱码）。

**CSV 列说明**

| 列 | 示例 | 说明 |
| --- | --- | --- |
| 码值 | `K7F2M9QX` | 唯一防伪码，用于系统校验 |
| 产品ID | `1` | 关联产品 |
| 产品名称 | `有机山茶油 500ml` | 便于印刷厂核对 |
| 批次号 | `B20261021-A` | 本次批次 |
| 扫码上限 | `3` | 该码允许的正常扫码次数 |
| H5链接 | `https://h5.yourdomain.com/scan/K7F2M9QX` | **印刷厂生成二维码的内容** |

> ⚠️ CSV 含全部防伪码，属于敏感资料。系统已禁止通过网址直接下载（`/uploads/csv/` 被 Nginx 拒绝），只能登录后台下载。请勿通过微信/邮件随意转发，交付印刷厂后删除本地副本。

### 4.5 交给印刷厂的标准话术

可将以下内容原样发给印刷厂：

```
1. 附件 CSV 中每一行对应一件产品，请按“H5链接”列的内容生成二维码（不要自行拼接或修改链接）。
2. 二维码纠错等级建议 M（或 H），最小印刷尺寸 20mm×20mm，四周留白 ≥ 3mm。
3. 深色包装请加白色底块；避免覆亮膜、烫金等影响识别的工艺。
4. 每一行的码必须与产品一一对应，不可重复使用同一行数据。
5. 印刷完成后请先提供 10 个样品，我方扫码验收后再批量生产。
6. 请勿把 CSV 上传到任何网盘或公共系统。
```

### 4.6 扫码验证效果

| 扫码次数 | 结果 |
| --- | --- |
| 第 1~3 次（阈值=3） | 绿色提示"正品验证通过，该码第 N 次被扫描" |
| 第 4 次及以后 | 红色闪烁预警"该码已被扫描 N 次，超过上限 3 次，请谨慎购买" |
| 无效码 | 提示"产品码不存在" |
| 已作废码 | 提示"产品码已失效" |

> 一物一码二维码内容为 **H5 短链**，微信内打开的是 H5 页面，同样可以完成防伪验证（非微信环境也正常）。

### 4.7 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| "单批次最多生成 100000 个" | 超出上限 | 拆分多个批次生成 |
| 生成进度不动 | 数据库/Redis 异常或线程池占满 | 联系运维查看日志 |
| 下载提示"批量任务尚未完成" | 状态仍为 RUNNING | 等待完成后再下载 |
| 下载提示"导出文件不存在或已过期" | 服务器文件被清理 | 重新生成该批次 |
| Excel 打开中文乱码 | 用非 Excel 软件打开了无 BOM 文件 | 使用 Excel 直接打开；或导入时选择 UTF-8 |
| 同一码第 2 次就预警 | 阈值被设为 1/2，或该码已被测试扫过 | 检查阈值；测试请使用不同码 |

## 5. 设置防伪验证阈值

### 5.1 阈值如何理解

系统对一物一码的判定逻辑：

```
第 1 次扫码 → 正常，计数 = 1
第 2 次扫码 → 正常，计数 = 2
第 3 次扫码 → 正常，计数 = 3（阈值 = 3）
第 4 次扫码 → 计数 = 4 > 3 → 红色假货预警，并写入预警日志
```

| 阈值 | 效果 | 建议 |
| --- | --- | --- |
| `0` | 不限制（仅普通产品码使用） | 普通宣传码 |
| `1` | 第 2 次扫码即预警 | 极易误报（消费者自己扫两次），不推荐 |
| `3` | 第 4 次预警 | **默认值，推荐** |
| `5` | 第 6 次预警 | 礼盒/需多次查看说明的产品 |
| `> 10` | 预警过于宽松 | 防伪意义减弱 |

> 阈值是"允许的正常扫码次数"，不是"触发预警的次数"。请向业务方解释清楚，避免误解。

### 5.2 修改全局阈值（影响后续新生成的批次）

**方式 A：后台界面（推荐）**

左侧 **系统设置 → 防伪阈值** → 修改"一物一码扫码上限" → 保存。

> 界面会提示：**该设置仅对之后新生成的一物一码生效，已生成的码不受影响**。

**方式 B：由运维修改配置**

编辑服务器上的 `/www/wwwroot/product-trace/backend/.env`：

```conf
ANTI_FAKE_SCAN_LIMIT=5
```

重启服务后生效（`systemctl restart product-trace`，或在宝塔 Java 项目管理器中重启）。

### 5.3 修改已生成批次的阈值

已生成的码在生成时已把阈值写入数据库（`product_code.scan_limit`），修改全局配置**不会**改变它们。请运维执行 SQL：

```sql
-- 1) 修改某批次全部码的阈值（建议先备份）
UPDATE product_code
SET scan_limit = 5
WHERE product_id = 1
  AND code_type = 2
  AND batch_no = 'B20261021-A';

-- 2) 修改单个码
UPDATE product_code SET scan_limit = 5 WHERE code = 'K7F2M9QX';

-- 3) 查询某批次当前阈值分布
SELECT scan_limit, COUNT(*) FROM product_code
WHERE batch_no = 'B20261021-A' GROUP BY scan_limit;
```

**让修改立即生效**（否则最多等 10 分钟缓存过期）：

```bash
# 清除该码的元信息缓存，下次扫码重新读库
redis-cli -a 'Redis密码' DEL trace:code:meta:K7F2M9QX

# 如需批量清除某批次（谨慎，按需执行）
redis-cli -a 'Redis密码' --scan --pattern 'trace:code:meta:*' | xargs -r redis-cli -a 'Redis密码' DEL
```

### 5.4 重置某个码的扫码次数

用于测试或售后复检（**会改变防伪判定结果，请谨慎并记录**）：

```sql
UPDATE product_code SET scan_count = 0, first_scan_time = NULL, last_scan_time = NULL
WHERE code = 'K7F2M9QX';
```

```bash
redis-cli -a 'Redis密码' DEL trace:code:scan:K7F2M9QX
redis-cli -a 'Redis密码' DEL trace:code:meta:K7F2M9QX
```

> 重置后该码重新获得完整的正常扫码次数。

### 5.5 阈值相关常见误解

| 误解 | 事实 |
| --- | --- |
| "改了全局阈值，所有码立刻变了" | 不会。只影响**之后新生成**的码；存量码需 SQL 修改 |
| "阈值越高越安全" | 相反。阈值越高，假货复用真码越难被发现 |
| "普通码也会预警" | 普通码 `scan_limit=0`，永不预警 |
| "改阈值会清零扫码次数" | 不会。计数独立保存，需单独重置 |

## 6. 查看扫码数据与防伪预警

### 6.1 后台页面

| 页面 | 位置 | 可查看内容 |
| --- | --- | --- |
| 数据概览 | 左侧 **数据概览** | 累计扫码量、今日扫码量、上架产品数、近 7 天趋势、预警数量 |
| 扫码记录 | **防伪与日志 → 扫码记录** | 码值、产品、扫码时间、IP、来源（小程序/H5）、结果、User-Agent |
| 假货预警 | **防伪与日志 → 假货预警** | 仅 `is_fake=1` 的记录，红色标记，可按产品/时间筛选 |

**筛选技巧**

- 按产品筛选：定位某个产品是否被大量扫码。
- 按时间筛选：排查某次促销/投放后的异常。
- 按 IP 排序：同一 IP 高频扫码，疑似刷码或复制真码测试。

### 6.2 数据字段解释

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| `scan_result` | 1 | 正常正品 |
| | 2 | 假货预警（超过阈值） |
| | 3 | 无效码（不存在/已失效/产品下架） |
| `is_fake` | 0 / 1 | 是否触发假货预警 |
| `scan_source` | 0 / 1 / 2 | 未知 / 微信小程序 / H5 |
| `scan_ip` | IP | 扫码用户公网 IP（经 Nginx 透传，未被伪造覆盖） |

### 6.3 用 SQL 查看统计（页面未开放时）

由运维在 phpMyAdmin 执行（数据库 `product_trace`）：

```sql
-- 1) 今日扫码总量
SELECT COUNT(*) AS today_scans
FROM scan_record
WHERE scan_time >= CURDATE();

-- 2) 近 7 天每日扫码趋势
SELECT DATE(scan_time) AS day, COUNT(*) AS scans
FROM scan_record
WHERE scan_time >= DATE_SUB(CURDATE(), INTERVAL 6 DAY)
GROUP BY DATE(scan_time)
ORDER BY day;

-- 3) 按产品统计（近 30 天）
SELECT p.product_name, COUNT(*) AS scans, SUM(s.is_fake) AS fake_count
FROM scan_record s
LEFT JOIN product p ON p.id = s.product_id
WHERE s.scan_time >= DATE_SUB(CURDATE(), INTERVAL 30 DAY)
GROUP BY p.product_name
ORDER BY scans DESC;

-- 4) 最新假货预警（最近 100 条）
SELECT code, product_id, scan_ip, scan_source, user_agent, scan_time
FROM scan_record
WHERE is_fake = 1
ORDER BY scan_time DESC
LIMIT 100;

-- 5) 无效码扫描（可能是假货或印刷错误）
SELECT code, scan_ip, scan_time
FROM scan_record
WHERE scan_result = 3
ORDER BY scan_time DESC
LIMIT 100;

-- 6) 24 小时内高频 IP（疑似刷码/测试）
SELECT scan_ip, COUNT(*) AS times
FROM scan_record
WHERE scan_time >= DATE_SUB(NOW(), INTERVAL 1 DAY)
GROUP BY scan_ip
HAVING times > 30
ORDER BY times DESC;

-- 7) 单个码的完整扫码轨迹
SELECT code, scan_ip, scan_source, scan_result, is_fake, scan_time
FROM scan_record
WHERE code = 'K7F2M9QX'
ORDER BY scan_time;
```

> 产品表中的 `view_count` 也会累计有效扫码/浏览次数，可在产品列表直接看"热度"。

### 6.4 发现预警后怎么处理

| 情形 | 判断 | 建议动作 |
| --- | --- | --- |
| 同一码在**不同省份/IP**短时间内多次扫描 | 真码被复制到假货 | 记录码值、批次，启动渠道核查；必要时作废该码 |
| 同一消费者重复扫码（同 IP、间隔短） | 正常误触 | 无需处理；可在客服话术中说明阈值规则 |
| 大量无效码（`scan_result=3`） | 印刷错误或伪造码 | 核对批次 CSV 与印刷样品 |
| 同一 IP 高频扫描多种码 | 竞品/黄牛爬取 | 联系运维调整限流参数（默认 30 次/分钟/IP） |
| 某批次预警率异常高 | 包装印刷重复用码 | 立即停发该批次，通知印刷厂返工 |

**作废单个码**

```sql
UPDATE product_code SET status = 0 WHERE code = 'K7F2M9QX';
```

作废后扫码提示"产品码已失效"，并记录为无效码。

## 8. 常见问题汇总

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 上传图片失败 | 图片过大 / 目录权限 / 服务器磁盘满 | 压缩到 5MB 内；联系运维查权限与磁盘 |
| 图片上传成功但前台不显示 | 域名/路径不一致、Nginx 防盗链 | 联系运维（见排障手册第 3 章） |
| 富文本保存后排版错乱 | 粘贴了外部网页样式 | 先在记事本清除格式，再用编辑器重新排版 |
| 视频无法播放 | 非 MP4/编码不支持、http 地址、防盗链 | 重新导出 H.264 MP4；使用 https 地址 |
| 二维码生成失败 | 小程序密钥/发布状态/额度 | 见 3.5 节 |
| 批量生成很慢 | 数量大 / 服务器繁忙 | 分批生成；避开高峰 |
| 扫码提示"产品不存在" | 码值错误或数据被删 | 用 CSV 原值核对；检查产品是否被删除 |
| 扫码提示"产品已下架" | 产品被下架 | 产品管理 → 上架 |
| 后台列表看不到刚建的产品 | 筛选条件/分页 | 清空筛选条件，回到第 1 页 |
| 后台操作提示"请求过于频繁"（429） | 防伪接口限流（30 次/分钟/IP） | 等待 1 分钟再试；批量测试请分时段 |
