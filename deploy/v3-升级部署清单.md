# 服务器升级执行清单 v3（v1.3.0 一次性升级）

**版本：** v1.3.0（2026-10-24，合并今日 v1.2.0 + v1.3.0 全部改动）

## 二、服务器升级步骤（严格按顺序）

### 第 0 步：停后端 + 备份

```bash
kill $(pgrep -f product-trace.jar) 2>/dev/null
sleep 3
pgrep -f product-trace.jar && kill -9 $(pgrep -f product-trace.jar)
echo "后端已停"

mysqldump -uroot -p product_trace \
  --default-character-set=utf8mb4 --single-transaction \
  > /root/product_trace_backup_$(date +%F_%H%M).sql
echo "备份完成：$(ls -lh /root/product_trace_backup_*.sql | tail -1)"

# 备份旧前端 dist（回滚用，必须先做）
tar -czf /root/admin-dist-backup-$(date +%F_%H%M).tgz \
  -C /www/wwwroot/product-trace/admin dist
echo "前端备份：$(ls -lh /root/admin-dist-backup-*.tgz | tail -1)"

# 清 Redis trace:* 缓存（后端会从 DB 重填，不丢数据）
redis-cli --no-auth-warning KEYS "trace:*" | xargs redis-cli --no-auth-warning DEL 2>/dev/null || true
```

### 第 1 步：按序执行 4 个迁移（幂等，可重复跑）

```bash
cd /root/product-trace-v1.3.0
for f in migration-v3.sql migration-v4.sql migration-v5.sql migration-v6.sql migration-v6-fix.sql; do
  echo "===== 执行 $f ====="
  mysql -uroot -p product_trace --force < $f    # v6-fix 报 1060 属预期，--force 继续
  echo "退出码：$?"
done
```

**校验输出（应看到 4 个 section 全部正常）：**

```bash
mysql -uroot -p product_trace -e "
```

```bash
# 3.4 健康检查
```

首登改密（**必做**，否则所有后台接口返回 code 2002）：

```bash
API=http://127.0.0.1:8080/api

TOKEN=$(curl -s -X POST $API/admin/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}' \
  | python3 -c 'import sys,json;print(json.load(sys.stdin)["data"]["token"])')

# 新密码要求：≥8 位，且同时含字母和数字
```

## 三、RBAC 角色权限验证（重点）

### 3.1 准备变量

```bash
API=http://127.0.0.1:8080/api
ADMIN_PWD='Admin@2026'    # 第 3 步改后的密码

TOKEN=$(curl -s -X POST $API/admin/auth/login -H 'Content-Type: application/json' \
  -d "{\"username\":\"admin\",\"password\":\"$ADMIN_PWD\"}" \
  | python3 -c 'import sys,json;print(json.load(sys.stdin)["data"]["token"])')
AUTH="Authorization: Bearer $TOKEN"
echo "TOKEN=${TOKEN:0:12}..."
```

### 3.2 超管权限（role_id 为 NULL = 超级管理员）

```bash
curl -s $API/admin/auth/info -H "$AUTH" | python3 -m json.tool
```

**期望：**
```
"roleId": null,
"permissions": ["product","code","stats","config","audit","media","system"]
```

### 3.3 新建角色（只给产品 + 二维码权限）

```bash
ROLE_ID=$(curl -s -X POST $API/admin/role -H "$AUTH" -H 'Content-Type: application/json' \
  -d '{"roleCode":"operator","roleName":"运营专员","description":"仅产品与码管理","permissions":"[\"product\",\"code\"]","status":1}' \
  | python3 -c 'import sys,json;print(json.load(sys.stdin)["data"]["id"])')
echo "ROLE_ID=$ROLE_ID"

# 分页接口应包含该角色
curl -s "$API/admin/role/page?current=1&size=20" -H "$AUTH" | python3 -m json.tool | head -30
```

**期望：** 返回 code=200，records 中出现 roleCode=operator、permissions 为 `["product","code"]`。

### 3.4 新建子账号 + 弱密码校验

```bash
# 正常创建
curl -s -X POST $API/admin/admin-user -H "$AUTH" -H 'Content-Type: application/json' \
  -d "{\"username\":\"operator1\",\"password\":\"Oper1234\",\"nickname\":\"运营一号\",\"roleId\":$ROLE_ID}" \
  | python3 -m json.tool
# 期望：code=200，返回中 password 为 null

# 弱密码（纯字母，缺数字）
curl -s -X POST $API/admin/admin-user -H "$AUTH" -H 'Content-Type: application/json' \
  -d "{\"username\":\"weaktest\",\"password\":\"abcdefgh\",\"roleId\":$ROLE_ID}" \
  | python3 -m json.tool
# 期望：code=2003，message=密码必须同时包含字母和数字

# 用户名重复
curl -s -X POST $API/admin/admin-user -H "$AUTH" -H 'Content-Type: application/json' \
  -d "{\"username\":\"operator1\",\"password\":\"Oper1234\",\"roleId\":$ROLE_ID}" \
  | python3 -m json.tool
# 期望：code=500，message 含「用户名已存在」
```

### 3.5 首登强制改密（必须改密才能操作业务）

```bash
OP_TOKEN=$(curl -s -X POST $API/admin/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"operator1","password":"Oper1234"}' \
  | python3 -c 'import sys,json;print(json.load(sys.stdin)["data"]["token"])')

# 未改密访问业务接口：HTTP 403 + 业务码 2002
curl -s -o /tmp/op-body.json -w "HTTP %{http_code}\n" "$API/admin/stats/overview" -H "Authorization: Bearer $OP_TOKEN"
cat /tmp/op-body.json
# 期望：HTTP 403，body {"code":2002,"message":"请先修改初始密码后再继续操作"}

# 改密 + 重新登录
curl -s -X POST $API/admin/auth/password -H "Authorization: Bearer $OP_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"oldPassword":"Oper1234","newPassword":"Oper5678"}' | python3 -m json.tool

OP_TOKEN=$(curl -s -X POST $API/admin/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"operator1","password":"Oper5678"}' \
  | python3 -c 'import sys,json;print(json.load(sys.stdin)["data"]["token"])')
```

### 3.6 越权校验（核心）

```bash
# 1) 无 system 权限 -> /admin/role/page 被拒（HTTP 200 + 业务码 403）
curl -s -o /tmp/a.json -w "role/page HTTP %{http_code}\n" "$API/admin/role/page" -H "Authorization: Bearer $OP_TOKEN"
cat /tmp/a.json
# 期望：HTTP 200，{"code":403,"message":"无权限操作"}

# 2) 无 stats 权限 -> 扫码统计被拒
curl -s -o /tmp/b.json -w "stats HTTP %{http_code}\n" "$API/admin/stats/overview" -H "Authorization: Bearer $OP_TOKEN"
cat /tmp/b.json
# 期望：code=403

# 3) 有 product 权限 -> 产品列表正常
curl -s "$API/admin/product/page?current=1&size=1" -H "Authorization: Bearer $OP_TOKEN" | python3 -m json.tool | head -8
# 期望：code=200

# 4) /info 返回该角色的权限
curl -s $API/admin/auth/info -H "Authorization: Bearer $OP_TOKEN" | python3 -m json.tool
# 期望：roleId=<ROLE_ID>，permissions=["product","code"]

# 5) 无 token 访问 -> 401
curl -s -o /tmp/c.json -w "no-token HTTP %{http_code}\n" "$API/admin/product/page"
cat /tmp/c.json
# 期望：HTTP 401，code=401
```

### 3.7 角色删除保护 + 权限缓存

```bash
# 角色已分配给 1 个管理员，删除应被拒绝
curl -s -X DELETE "$API/admin/role/$ROLE_ID" -H "$AUTH" | python3 -m json.tool
# 期望：code=500，message 含「该角色已分配给 1 个管理员，无法删除」

# 权限缓存（10 分钟 TTL）
```

## 七、回滚方案

```bash
# 1. 停服务
kill $(pgrep -f product-trace.jar); sleep 2

# 2. jar 回滚
cp /www/wwwroot/product-trace/api/product-trace.jar.bak \
   /www/wwwroot/product-trace/api/product-trace.jar

# 3. 数据库回滚（仅在数据被写坏时才做，会丢失升级后新增数据）
mysql -uroot -p product_trace < /root/product_trace_backup_YYYYMMDD_HHMM.sql

# 4. admin-web 回滚：用第 0 步的备份包还原
rm -rf /www/wwwroot/product-trace/admin/dist
tar -xzf /root/admin-dist-backup_YYYYMMDD_HHMM.tgz -C /www/wwwroot/product-trace/admin
chown -R www:www /www/wwwroot/product-trace/admin/dist

# 5. 清 Redis + 重启
redis-cli --no-auth-warning KEYS "trace:*" | xargs redis-cli --no-auth-warning DEL 2>/dev/null || true
cd /www/wwwroot/product-trace/api && nohup java -jar \
  -Xms512m -Xmx1024m -Dspring.profiles.active=prod \
  product-trace.jar > ../../logs/app.out.log 2> ../../logs/app.err.log &

sleep 10 && curl -s http://127.0.0.1:8080/api/health
```

> 旧 jar 不识别新增表和字段，保留它们不影响回滚；无需删表。
