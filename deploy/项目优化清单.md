## 🔴 P0 — 安全（生产环境必须处理）

### 1. 管理员登录无暴力破解防护
**证据：** [AuthService.java:30-48](file:///D:/Trae/product-trace/src/main/java/com/trace/product/service/AuthService.java#L30-L48) — 登录失败只抛业务异常，没有失败计数 / 锁定 / 验证码

**建议：**
- Redis 记录失败次数：`trace:login:fail:{username}`，5 次失败锁 30 分钟
- 登录接口加图形验证码（前后端联动）

### 2. admin 默认密码 admin123 一直能用
**证据：** [sys_admin 表](file:///D:/Trae/product-trace/deploy/v2-升级部署清单.md#L121) — 部署脚本里还是 `admin/admin123`

**建议：**
- 首次登录强制改密码（数据库加 `must_change_password` 字段）
- 密码复杂度校验（至少 8 位 + 大小写 + 数字）
- 增加「最后登录时间 / IP」记录，异常登录时给管理员发邮件/企业微信

### 3. CORS 完全开放
**证据：** [WebMvcConfig.java](file:///D:/Trae/product-trace/src/main/java/com/trace/product/config/WebMvcConfig.java) — 没看到 CorsConfiguration 配置，Spring Boot 默认或 Nginx 允许所有 origin

**建议：** 只允许 `admin.example.com`、`h5.example.com`，禁止 `*`（生产环境）

### 4. Nginx 缺安全响应头
**证据：** [bt_nginx_api.conf](file:///D:/Trae/release/product-trace-v1.0.0-20261022/06-nginx/bt_nginx_api.conf) — 没配置 HSTS / X-Frame-Options / X-Content-Type-Options

**建议：**
```nginx
add_header Strict-Transport-Security "max-age=31536000" always;
add_header X-Frame-Options "SAMEORIGIN" always;
add_header X-Content-Type-Options "nosniff" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
```

### 5. 扫码 IP 限流过松
**证据：** [VerifyRateLimitInterceptor.java](file:///D:/Trae/product-trace/src/main/java/com/trace/product/interceptor/VerifyRateLimitInterceptor.java) 当前 `limit=30 / 60s`

**建议：**
- 单 IP 每分钟 ≤ 10 次
- 单码每小时 ≤ 20 次（防羊毛）
- 触发限流后返回 429 + 验证码挑战（而不是直接拒绝）

## 🟠 P1 — 数据库 / 性能

### 6. scan_record 表没有任何索引（除了主键）
**证据：** `SHOW INDEX FROM scan_record` 只有 PRIMARY；[ScanLogService.java:25-46](file:///D:/Trae/product-trace/src/main/java/com/trace/product/service/ScanLogService.java#L25) 每扫码一次就 INSERT

**问题：** 百万级数据后，扫码统计、按码查询、按时间范围查询都会全表扫描

**建议：**
```sql
ALTER TABLE scan_record
  ADD INDEX idx_code_id (code_id),
  ADD INDEX idx_code (code),
  ADD INDEX idx_scan_time (scan_time),
  ADD INDEX idx_product_id (product_id),
  ADD INDEX idx_scan_result (scan_result),
  ADD INDEX idx_scan_ip (scan_ip);
```

### 7. scan_record 无归档策略，会无限膨胀
**证据：** 没有任何 DELETE / ARCHIVE / PARTITION 逻辑

**建议：**
- 按月分表（`scan_record_202610`）或者用 MySQL 分区
- 定时任务：90 天前的数据归档到 OSS / 冷备库
- 后台统计直接查汇总表，不查原始明细

### 8. product_code 大数据量分页慢
**证据：** [ProductCodeMapper.xml](file:///D:/Trae/product-trace/src/main/resources/mapper/ProductCodeMapper.xml) `selectPageWithProduct` 用了 `LEFT JOIN product` + `ORDER BY c.id DESC LIMIT`

**问题：** 当 product_code 表到 100 万行时，`COUNT(*)` 子查询会慢

**建议：**
- 用 `KEY idx_product_id (product_id, id)` 复合索引覆盖
- 或者改用「延迟关联」（先查 ID 再回表）

### 9. upload 目录孤儿文件无清理
**证据：** `removeCodes` 删除了引用文件，但**用户上传后又删除产品**时，产品图片/视频没人删

**建议：**
- 定时任务扫描：DB 里所有被引用的 URL → 反向找磁盘文件 → 删孤儿
- 或者上传后先入「待引用」池，产品保存时再把 URL 移入正式字段（删除时级联）

### 10. CSV 文件无清理
**证据：** [BatchCodeService.java:130](file:///D:/Trae/product-trace/src/main/java/com/trace/product/service/BatchCodeService.java#L130) CSV 写到 `mediaStorageProperties.rootPath/csv/{taskId}.csv` 后永久保留

**建议：**
- crontab 每周日清理 30 天前的 CSV
- 或者数据库 `batch_code_task` 表里加 `expired_at` 字段，下载后过期

## 🟡 P2 — 缺失的核心功能

### 11. 没有用户行为审计日志
**证据：** 全局 grep 找不到 `create_by` / `update_by` / `operation_log` / `auditor` 字段

**问题：** 谁在什么时间作废了码、删了产品、改了配置 —— 完全无迹可查

**建议：**
- 新建 `admin_operation_log` 表：admin_id / module / action / target_id / before_json / after_json / ip / created_at
- 关键操作（作废码 / 删除产品 / 修改站点配置）通过 AOP 切面自动记录

### 12. 扫码没记录地理位置
**证据：** [ScanRecord.java](file:///D:/Trae/product-trace/src/main/java/com/trace/product/entity/ScanRecord.java) 没有 `scanLat` / `scanLng` / `province` / `city` 字段

**建议：**
- 表加：`scan_lat` / `scan_lng` / `province` / `city`
- H5 详情页用 HTML5 Geolocation API（用户授权后）+ IP 地理反查（腾讯位置服务 / 高德）兜底
- 后台加个「扫码分布地图」页面（按省/市聚合，高亮高危地区）

### 13. 扫码没有触发微信订阅消息
**建议：**
- 用户首次扫码时引导订阅（微信小程序 / 公众号）
- 码作废、产品下架、批量码被扫出异常 → 主动推送通知

### 14. 后台没有角色权限（RBAC）
**证据：** [sys_admin 表](file:///D:/Trae/product-trace/src/main/java/com/trace/product/mapper/SysAdminMapper.java) 只有 username/password/role，role 是单字段不是角色表

**建议：**
- 新建 `sys_role` / `sys_permission` / `sys_admin_role` 三表
- 至少分：超级管理员 / 运营（只能查）/ 客服（只能处理反馈）
- 按钮级权限：`v-if="$auth('code:delete')"`

### 15. 没有批量导入产品
**建议：**
- 后台「产品管理」加 Excel 导入（EasyExcel）
- 模板：货号 / 品名 / 品牌 / 规格 / 零售价 / 分类
- 导入失败给行级错误反馈

### 16. 没有打印对接
**建议：**
- 一物一码生成后支持「热敏打印机直连」（佳博 / 得力 API）
- 或者批量导出 PDF（含二维码 + 文字说明），直接印刷

## 🔵 P4 — 运维 / 部署

### 22. 没有 Prometheus / Actuator 监控
**建议：**
- `pom.xml` 加 `spring-boot-starter-actuator` + `micrometer-registry-prometheus`
- 暴露 `/actuator/health` `/actuator/metrics`，Prometheus 拉取 → Grafana 展示
- 关键指标：JVM 内存、扫码 QPS、码生成 QPS、Redis 命中率

### 23. 没有自动化备份脚本
**建议：** crontab 每日 03:00：
```bash
mysqldump product_trace | gzip > /backup/db_$(date +%F).sql.gz
tar czf /backup/upload_$(date +%F).tar.gz /www/wwwroot/product-trace/upload
# 保留 30 天
find /backup -mtime +30 -delete
```

### 24. 启动脚本不健壮
**建议：** `start.sh` 检查：
- 端口 8080 是否被占用
- JVM 参数是否合理（生产建议 `-Xms1g -Xmx2g -XX:+UseG1GC`）
- 日志目录是否存在
- 失败时告警（企业微信 webhook）

### 25. 没有灰度 / 蓝绿发布
**建议：** 至少做滚动重启：先启新 jar 在 8081，Nginx 切流量，确认健康后停旧的
