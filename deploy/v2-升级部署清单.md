## 🚀 二、服务器升级步骤（严格按顺序）

### 第 0 步：停后端 + 数据库备份（必做！）

```bash
# 0.1 停后端
kill $(pgrep -f product-trace.jar) 2>/dev/null
sleep 3
pgrep -f product-trace.jar && echo "还在跑，强杀" && kill -9 $(pgrep -f product-trace.jar)
echo "后端已停"

# 0.2 数据库备份（留个底，万一 SQL 改坏可以回滚）
mysqldump -uroot -p product_trace \
  --default-character-set=utf8mb4 \
  --single-transaction \
  > /root/product_trace_backup_$(date +%F_%H%M).sql
echo "备份完成 $(date +%F_%H%M)，大小：$(du -h /root/product_trace_backup_*.sql | tail -1)"

# 0.3 Redis 清 trace:* 缓存（清了不丢数据，后端会从 DB 重填）
redis-cli --no-auth-warning KEYS "trace:*" | xargs redis-cli --no-auth-warning DEL 2>/dev/null || true
echo "Redis trace:* 缓存已清"
```

### 第 1 步：执行 SQL 迁移（幂等，放心跑）

```bash

# 验证：两条都应该显示"字段存在"，不要有 ERROR
echo ""
echo "=== product_code 新字段 ==="
mysql -uroot -p -e "USE product_trace; SHOW COLUMNS FROM product_code LIKE 'void_scan_count'; SHOW COLUMNS FROM product_code LIKE 'over_limit_scan_count';"

echo ""
echo "=== batch_code_task 新表 ==="
```

#### 7.2 扫码分类全流程（核心新功能）

```bash
# 先找一个 scan_limit > 0 的码
LIMIT_CODE=$(mysql -uroot -p -N -e "SELECT code FROM product_trace.product_code WHERE scan_limit>0 AND deleted=0 LIMIT 1;")
echo "扫码测试码：$LIMIT_CODE"
LIMIT=$(mysql -uroot -p -N -e "SELECT scan_limit FROM product_trace.product_code WHERE code='$LIMIT_CODE';")
echo "上限：$LIMIT"

# 清 Redis 缓存
redis-cli --no-auth-warning DEL "trace:code:meta:$LIMIT_CODE" "trace:code:scan:$LIMIT_CODE"
mysql -uroot -p -e "UPDATE product_trace SET scan_count=0, void_scan_count=0, over_limit_scan_count=0 WHERE code='$LIMIT_CODE';"

# 连续扫 LIMIT+2 次（比如上限是 3，扫 5 次）
echo ""
echo "=== 连续扫码测试 ==="
for i in $(seq 1 $((LIMIT + 2))); do
  RESULT=$(curl -s "http://127.0.0.1:8080/api/verify/$LIMIT_CODE")
  echo "第 $i 次：$(echo $RESULT | python3 -c 'import sys,json; d=json.load(sys.stdin); print(f"fakeWarning={d[\"data\"][\"fakeWarning\"]} overLimitContinue={d[\"data\"].get(\"overLimitContinue\")} count={d[\"data\"][\"scanCount\"]}")' 2>/dev/null)"
done

# 最终 scan_record 分布
echo ""
echo "=== scan_result 分布 ==="
mysql -uroot -p -e "SELECT scan_result, COUNT(*) cnt FROM product_trace.scan_record WHERE code='$LIMIT_CODE' GROUP BY scan_result;"
# 期望：scan_result=1 有 LIMIT 次，scan_result=2 有 1 次（首次超限），scan_result=5 有 1 次（续扫）

# 作废码测试
echo ""
echo "=== 作废这个码 ==="
mysql -uroot -p -e "UPDATE product_trace SET status=0 WHERE code='$LIMIT_CODE';"
redis-cli --no-auth-warning DEL "trace:code:meta:$LIMIT_CODE"
echo "=== 作废后扫码（scanResult=4）==="
curl -s "http://127.0.0.1:8080/api/verify/$LIMIT_CODE" | python3 -m json.tool 2>/dev/null | grep -E "valid|voidWarning|message"
# 期望：valid=false, voidWarning=true, 消息含"已被商家作废"
```

## ⏪ 三、回滚方案（升级出问题时）

```bash
# 1. 停后端
kill $(pgrep -f product-trace.jar)
sleep 2

# 2. 数据库回滚（恢复备份）
mysql -uroot -p product_trace < /root/product_trace_backup_YYYYMMDD_HHMM.sql

# 3. jar 回滚（如果 v1 备份过）
cp /www/wwwroot/product-trace/api/product-trace.jar.bak \
   /www/wwwroot/product-trace/api/product-trace.jar

# 4. admin-web 回滚
git checkout -- /www/wwwroot/product-trace/admin/dist/   # 如果用 git 部署
# 或者重新上传旧的 dist/

# 5. 重启
cd /www/wwwroot/product-trace/api && nohup java -jar \
  -Xms512m -Xmx1024m \
  -Dspring.profiles.active=prod \
  product-trace.jar > ../../logs/app.out.log 2> ../../logs/app.err.log &

# 6. 验证
sleep 10 && curl -s http://127.0.0.1:8080/api/health
```

## 📋 四、本次升级改动汇总（参考）

| 模块 | 改动点 | 影响范围 |
|---|---|---|
| SQL | product_code 加 void_scan_count / over_limit_scan_count 列；新建 batch_code_task 表 | 数据库结构（v1→v2 迁移） |
| 后端-VerifyService | 扫码分 5 类：1=正常 / 2=首次超限 / 4=作废码 / 5=超限续扫 | 扫码验证接口返回值 |
| 后端-MediaController | 图片限 JPG/PNG/WebP ≤2MB，视频限 MP4/WebM ≤50MB | 上传接口报错信息 |
| 后端-ProductCodeService | startBatch 接 scanLimit 透传，同步写 batch_code_task | 一物一码生成逻辑 |
| 后端-BatchCodeService | execute 接 scanLimit 参数，CSV 写实际值，成功/失败同步 UPDATE batch_code_task | 异步任务闭环 |
| 后端-ProductCodeController | 新增 GET /admin/code/batch/list 历史批次分页接口 | 管理后台新接口 |
| 前端-admin-web CodeManage | scanLimit 输入框、历史批次面板、行高亮、违规扫码列 | 二维码管理页面 |
| 前端-admin-web ProductList | 上传按钮旁灰色规格提示文字 | 产品编辑页面 |

**不影响：** H5 用户端、微信小程序、Nginx 配置、已存在的产品数据和图片文件。
